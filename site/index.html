Why it exists

Installers, SDKs and tutorials keep asking you to "add this to your environment". On Windows that means a small dialog several clicks deep, with PATH as one long line. On macOS and Linux it means export lines spread across .bashrc, .zshrc and friends.

Then the terminal you already have open doesn't notice the change, nothing tells you when JAVA_HOME points to a JDK you removed last year, and one wrong edit to PATH breaks every command, with no undo.

What it does

Finds what's broken
Values that point to folders or files that don't exist are marked red, down to the single missing folder in PATH.
Updates open terminals
One click and PowerShell, Git Bash, bash, zsh and fish pick up your changes before their next prompt.
Can't break your system
Only your own variables are ever written, never system ones, so it never asks for administrator rights.
Undo for everything
A backup is taken before every change. Undo is one click, and the original state from before VARden is kept forever.
Keeps secrets secret
API keys and passwords are masked on screen. A copied secret stays out of clipboard history and is cleared after 30 seconds, and secrets saved in profiles go to your system's password store.
Profiles and .env files
Switch a whole set of variables per client or project at once, and import or export .env files.
Rename and edit in bulk
Rename a variable in place, delete or export several at once, and see changes made by other tools appear without a refresh.
Waits in the tray
Sync open terminals from the tray icon without opening the window, and start VARden with your computer if you like.
Keeps itself up to date
New versions install with one click. Every update is signed, and VARden refuses one whose signature doesn't match.

Edit PATH as a list you can trust

Add, remove and reorder your own folders. The system part is shown but locked. Each folder is checked as you type, and nothing is saved until you've reviewed exactly what changes.

Read long values without squinting

Open any long value right in the list. PATH shows one folder per line, with the ones that don't exist in red. Copy the whole value with one click.

Go back to any earlier state

Backups are grouped by day. Before restoring one, you see exactly which variables would come back, change or disappear, and the restore itself can be undone too.

How Sync to terminals works

Programs read environment variables once, when they start. That's why tutorials say "restart your terminal". VARden adds a tiny, clearly marked hook to each shell you choose, and then:

  1. You click Sync to terminals. VARden writes the new values to its own folder and bumps a counter.

  2. You press Enter in any open terminal. Before drawing the next prompt, the hook reads the counter: one tiny file read.

  3. The counter changed, so the terminal updates. Variables are set or removed, and PATH is merged folder by folder, so an active virtualenv survives.

VARden only ever writes where your account keeps its variables: HKEY_CURRENT_USER\Environment on Windows, a marked block in your startup file on macOS and Linux. It doesn't need to be running for your variables to work.

Questions

Is it safe? Could it break my computer?

VARden only writes variables that belong to your account, never system-wide ones, so it can't affect other accounts or Windows itself. Every change is backed up first and can be undone, and the very first backup of each place it writes to is kept forever.

I changed a variable but my terminal still has the old value.

Programs read variables once, when they start. Either open a new terminal, or install terminal sync for your shell on VARden's Shells page; after that, Sync to terminals updates open ones. Other programs, like your editor, need a restart.

Are my API keys stored securely?

VARden stores values exactly where your system expects them (the registry, or your shell's startup file), because that's what programs read. It masks secrets on screen, clears copied secrets from the clipboard after 30 seconds, and never writes values to its log. Secrets in profiles are kept in Windows Credential Manager, the macOS keychain or your Linux keyring, and backups sit in a folder only your account can open.

Do I need to install anything else first?

No. Download the installer for your system and run it; you don't need Git, Rust, Node.js or a terminal. On Windows, VARden uses the Edge WebView2 component that comes with Windows 10 and 11, and the installer downloads it if it's missing. On Linux, the .deb and .rpm packages pull in what they need through your package manager, and the AppImage brings everything with it.

Something went wrong. How do I report it?

Open Settings in VARden and choose Report a problem. It shows a cleaned copy of its log, with variable names, your user name and anything that looks like a key replaced, and only lets you copy it after you've checked it. Then it opens a GitHub issue with your version and system filled in.

Why can't I edit system variables?

On purpose. System variables affect every account and need administrator rights, so a mistake is much harder to undo. VARden shows the system part of PATH read-only so you see the whole picture.

Windows or macOS warns me before opening it. Is that normal?

Yes, for now. VARden isn't signed with a paid certificate yet, so your system doesn't recognise it. On Windows, click More info, then Run anyway. On macOS, right-click VARden in Applications, choose Open, then Open again. You only need to do this once, and updates installed from inside VARden don't ask again.

Does VARden send any data?

No telemetry, no account. The only request it makes is a check for new versions on GitHub when it starts, which you can turn off in Settings. Updates are signed, and VARden refuses any update whose signature doesn't match.

What happens if I uninstall it?

Your variables stay; they belong to your account. On Windows the uninstaller also removes VARden's terminal-sync lines from your shell profiles. On macOS and Linux, remove terminal sync on the Shells page before deleting the app.
