Code signing policy

Current status

VARden's installers are not signed with a code-signing certificate yet, so Windows and macOS warn the first time you open them. VARden is applying for free Windows code signing from the SignPath Foundation, which signs open-source projects. Once approved, Windows installers will be signed in GitHub Actions from this repository's public source, and this page will say so.

Every update VARden installs by itself is signed with VARden's own update key, whatever the status above. VARden refuses an update whose signature doesn't match.

What gets signed

Only VARden's own programs and installers, built from the public source code in the GitHub repository by GitHub Actions (release workflow). Nothing built on a personal computer is signed, and no third-party programs are signed with VARden's certificate.

Who can approve a release

Authors
Ramez Chreide (@RamezCh). Outside contributions are reviewed before they're merged.
Reviewers
Ramez Chreide
Approvers
Ramez Chreide. Every signed release is approved by hand.

All team members use multi-factor authentication for GitHub and for signing.

Privacy

VARden doesn't collect or send any information about you or your variables. The one network request it makes is a check for a newer version on GitHub when it starts, which you can turn off in Settings. Problem reports are written and sent by you, through GitHub; VARden only prepares a cleaned copy of its log for you to review first.
